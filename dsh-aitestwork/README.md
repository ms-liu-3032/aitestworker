# AITestWork for DeepSeek Harness

本机 DSH 插件可独立设计用例并用 Playwright 执行 UI 自动化；需要跨设备资产时，也可连接远程 AITestWork 原有后端。DSH 负责推理、测试设计和执行；AITestWork 提供项目、TOM、Wiki、正式用例、草稿、自动化资产、权限和证据服务。原 Web 页面与功能继续保留；插件不启动第二套后端。

当前插件版本为 `0.1.71`。本地 UI/API 执行完成后会更新并打开同一个本地报告首页；每条用例仍保留单独的 HTML 报告、截图与原始证据。报告显示用例执行结果，项目级规则覆盖仍以对应的覆盖检查结果为准。UI 映射在没有可观察重置状态时可使用 `{ "type": "wait", "timeoutMs": 500 }` 固定等待，单步 100–30000 毫秒、整份映射累计最多 60000 毫秒；等待后仍需断言。

## 跨项目自动化复用

连接到新版 AITestWork 后，对自然语言自动化任务先调用 `aitestwork_prepare_auto_execution`。工具查询本项目有效映射、已发布复用版和已审核系统级版；采用跨项目版本用 `aitestwork_adopt_reusable_automation`，会在目标项目生成待验证映射。只有真实执行并保留证据后，才能审核及日常复跑。发现候选但确实不适用时，创建新映射需提供 `freshReason`。服务端和 Web 须先升级至包含 Work V76 的同一版本，再安装本插件。

## 日志连接

0.1.58 支持 UI/API 映射中的日志规则、服务发现、请求关联、规则复用及结果回写。使用时提供完整日志平台根 URL（含自定义部署路径），不从测试地址推导，也不自动追加固定登录路径。默认打开该 URL，由平台跳转登录；必要时可另给完整同源 loginUrl。凭据只在独立登录窗口输入，不写入映射。当前适配 Spring Boot Admin 实例/日志接口；协议内的相对 API 路径与用户部署前缀分开，不代表任意日志平台通用适配。

规则随资产版本审核复用，后端只收受限摘要和哈希；底层独立工具仍仅本机保存。只支持新增完整行的正向匹配，读取不完整不能算通过。首次启用日志结果回写须升级原有后端（Work V74）及 Web，无需新建服务。无人值守登录尚未实现。

## 构建与分享

当前版本的插件 ID、Skill、工具、绑定命令和服务端 DSH 接口统一使用 AITestWork 命名。升级时先部署本仓库对应的后端与 Web，再安装新插件并重新绑定；此前的 DSH 会话不会自动获得新工具名。本机旧凭据与旧版本地目录不会被删除，也不会自动读取，迁移前请保留备份。

0.1.60 增加 DSH 执行前审批：选择 TOM 模式、首次对某项目及站点执行 UI/API/本地测试或启动采集时，必须通过 DSH 审批界面；无审批服务或拒绝时停止。同一连接、项目和站点的执行许可最多保留 8 小时，换地址重新确认。审批不是服务端防绕过机制，拥有本机凭据和终端权限的进程仍可直接调用后端接口；后端继续执行原有资产与方法论校验。

在仓库根目录运行：

```bash
./packaging/build-dsh-plugin-package.sh
```

脚本构建共享浏览器采集模块和插件，在 `release/dsh-plugin/` 生成一个 `.tgz` 文件与 `INSTALL.md`。把这两个文件交给使用者即可；不要分享本机的 `.env`、数据库、证据和 `node_modules`。插件包中已包含 Skill 和采集代码，使用者无需再打开独立 worker 窗口。

开发者也可在本目录运行 `npm ci --install-links && npm test`。插件要求 DeepSeek Harness Desktop 版本满足 `package.json` 中的 `engines.dsh`，本机浏览器执行需要 Chrome 或 Playwright Chromium。

## 使用

1. 在 DSH 插件页添加 `.tgz`，重启并确认插件已启用。
2. 不连接 AITestWork 时，直接说“按这份需求先列测试点，再设计独立用例并保存在本机”。本地设计有唯一 ID 和版本，保存在 `~/.dsh/aitestwork-local/designs/`。继续说“给这条用例建立 Playwright 映射并执行”，报告、截图、trace 和录屏只保存在本机，结果标记 `LOCAL_ONLY`。
3. 需要项目 TOM、Wiki、正式用例或证据回写时，在 AITestWork Web 登录生成一次性绑定码，复制完整绑定命令到 DSH。模型 API Key 与 AITestWork 连接凭据分别由 DSH 和 AITestWork 管理。
4. 绑定后直接用自然语言创建项目、分析需求、生成测试点和用例、执行 UI/API 自动化或查看证据。插件会读取 AITestWork 的项目资产与规则，写入个人草稿前调用校验；正式用例仍由人在 AITestWork 审核。
5. 每次 UI/API 自动化执行后，工具结果显示执行状态和本地 HTML 报告路径。仅在联机模式下，执行证据才按采集会话上传 AITestWork。

Skill 只规定跨业务的测试方法与来源使用顺序。具体菜单、接口路径、定位器、测试数据和断言保存在本地设计或当前项目的自动化资产中，不写进 Skill。本地模式仅依据本轮需求与实测页面，不能声称读取 AITestWork 规则或通过 AITestWork 审核。定位失败时只修复定位，不擅自更改断言。

滚轮控件可在 UI 映射步骤中使用 `scroll`（Playwright `mouse.wheel`）；不响应滚轮的控件可尝试 `drag`（从目标中心按下、移动、松开）：

```json
[
  {"type":"scroll","locator":{"by":"css","value":".picker-column"},"deltaY":120,"repeat":2},
  {"type":"drag","locator":{"by":"css","value":".picker-column"},"deltaY":-120,"dragSteps":12}
]
```

以上是步骤示意，需放进用例的 `steps` 数组，并在 `assertions` 中检查实际选中值。`scroll` 的 `deltaY` 为非零整数且绝对值不超过 2000，`repeat` 为 1–10；`drag` 的 `deltaX` 或 `deltaY` 至少一项非零且各不超过 ±2000，`dragSteps` 为 2–50。方向与距离须按目标页面实测。`drag` 使用鼠标指针事件；只接受触摸事件的控件需要单独验证，不能把模拟执行通过当成真实页面通过。

## 安全与数据

插件不内置服务器地址、授权码或账号。连接凭据保存在本机 DSH 凭据服务中；后端按绑定用户检查项目权限。HTTP 连接只适用于可信内网，外部访问应使用 HTTPS。自动化与采集可能产生包含业务数据的截图、网络记录或录屏，分享报告前应自行核对内容。

## 维护

后端接口、Web 管理页、DSH 插件和打包脚本在同一仓库维护。修改插件后重新运行打包脚本并把新 `.tgz` 发给使用者；修改后端或 Web 则使用原服务端打包脚本升级。两种包分别安装。
